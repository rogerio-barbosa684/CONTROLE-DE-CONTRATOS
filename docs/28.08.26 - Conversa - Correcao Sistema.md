## Resumo da Sessão
Data: 28 de agosto de 2026
Contexto: Correção de bugs críticos no sistema de Controle de Contratos e Pagamentops
Plataforma: Netlify + Supabase + IndexedDB

---

## Problemas Identificados e Corrigidos

### 1. "The database connection is closing" (Erro IndexedDB)
**Sintoma:** `InvalidStateError: Failed to execute 'transaction' on 'IDBDatabase': The database connection is closing`
**Causa:** Funções `save*` do IndexedDB não tinham proteção contra DB fechando
**Correção:** Todas as funções `save*` receberam `try-catch` e verificação `if (!db)`
- saveContratos, savePagamentos, saveCertidoes, saveLicitacoes
- saveDestinatarios, saveTipos, saveEmpresas, saveSectors
- saveUserEmpresas, saveUserSetores

### 2. ParcelasManuais Multiplicando
**Sintoma:** Ao salvar contrato avulso, parcelas multiplicavam (4→8→12→...→48)
**Causa:** `salvarContrato()` não verificava `_saveSyncRunning` no início — cliques múltiplos entravam na função
**Correção:** Guard `if (_saveSyncRunning)` no início de `salvarContrato()`

### 3. Sessão JWT Expirada (401)
**Sintoma:** Toast "Erro ao enviar" durante sync
**Causa:** Token JWT expirava (expiresIn: 8h) e o frontend não tratava 401
**Correção:** `syncToServer()` e `loadFromServer()` agora detectam 401 → redirecionam para login

### 4. db.onversionchange Handler
**Sintoma:** DB fechava silenciosamente quando outra aba alterava versão
**Correção:** Adicionado handler que recarrega a página automaticamente

### 5. Contratos/Pagamentos Não Sincronizavam Entre Máquinas (PROBLEMA RAIZ)
**Sintoma:** Contrato criado na máquina A não aparecia na máquina B. Certidões funcionavam.
**Causa:** Relógio do navegador (cliente) dessincronizado do servidor:
  - `loadFromServer()` definia `_lastSyncAt = server_now` (ex: 14:00)
  - `now()` retornava hora LOCAL (ex: 13:58 — 2min atrás)
  - Filtro `onlyChanged`: `13:58 > 14:00` → **FALSE** → registro **nunca era enviado**

**Correção definitiva (commit 874a5a9):**
- `syncToServer()` **SEMPRE envia TODOS os registros** ao servidor (eliminado filtro `onlyChanged`)
- `loadFromServer()` **SEMPRE faz GET full** (eliminado `?since=` do delta)
- Servidor deduplica via `updated_at` comparison (server-side, um único relógio)
- Arquivos stripped em registros antigos, mantidos em registros novos

## Arquitetura de Sync Final

```
Máquina A (IndexedDB) ←→ API (Netlify Functions) ←→ Supabase ←→ API ←→ Máquina B (IndexedDB)
```

### Fluxo de Sincronização (a cada 30s):
1. **GET /api/sync** → Recebe TODOS os dados do servidor (full sync)
2. **mergeDelta()** → Merge com cache local (mantém o mais novo)
3. **POST /api/sync** → Envia TODOS os registros locais ao servidor
4. **Servidor** → Compara `updated_at`, mantém a versão mais recente

### Conflitos:
- Resolvidos por **timestamp** (`updated_at`) — server-side
- Se cliente envia registro com `updated_at` menor → servidor ignora
- Se cliente envia registro com `updated_at` maior → servidor atualiza

## Configurações Importantes

- **MAX_BASE64:** 4MB por arquivo (limite Netlify: 6MB)
- **Sync periódica:** 30 segundos
- **Retry automático:** 10 segundos quando sync falha (`_pendingSync`)
- **JWT expiry:** 8 horas
- **Soft deletes:** `deleted_at` em pagamentos/additives/certidoes/licitacoes/destinatarios; `active=0` em contratos
- **Migração Supabase:** `updated_at`, `deleted_at`, `sync_log` (já executada)
